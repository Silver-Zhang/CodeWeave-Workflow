# M2 executable acceptance contract — proposed v2

Every case records source Git+dirty manifest, snapshot/profile/index IDs, toolchain/analyzer/protocol, actual argv/exit/JSON, and old/new buffer hashes. Fixtures are owned multi-file Git projects with expected entities, per-TU observations, calls and byte extents authored **before** analysis. No analyzer means failure, not all-Skip acceptance. Unit/database fake facts cannot replace real Clang/CLI/browser evidence. No production implementation is claimed here.

Layers: **C** real freshly built Clang+Bubblewrap integration; **D** SQLite contract (explicit seeded schema rows permitted, labeled); **L** separate public CLI processes; **H** HTTP adapter/security; **B** real Chromium with real indexes. Browser delay/error injection may control timing or failure only, never synthesize successful facts.

M2-A gate: 01–20 +22 implemented and passing, real C/L/H/B actually executed, no open safety/identity/snapshot/deletion/output-boundary blocker. Cases describe absent capability as future failure until implemented; R0 acceptance concerns design feasibility, not these implementation PASSes.

M2-B gate: A remains passing; 04–08/10/13–17/21–22 additionally assert invalidated/reused TU **exact sets**, per-TU artifact provenance and normalized incremental==full results across all supported edit cases. Published candidate initially requires shadow full equality; preserve mismatch evidence/fallback. Measure capture IO, analyzed/reused counts, merge, shadow overhead, total wall time and cold/warm distributions on owned fixtures. Report no-gain/over-invalidated cases; do not declare production speedup from cache-only timing.

Future implementation harness should expose only timing/failure control hooks in test-owned wrappers; no rewriting facts, analyzer success codes or expected results. Each required negative case has a normal positive control to detect over-rejection. Unsupported PCH/modules, full implicit calls, runtime branch execution, whole-program virtual dispatch, large private-project performance and unsaved editor buffers are out of scope explicitly.

Additional identity oracle: dirty snapshots have base_git_head provenance and represented_git_commit=null, even if Git status ignores the changed input. Hash identity includes compiler-relevant metadata; token/AST call-pairing algorithm is verified on unique target replacement and ambiguous repeats separately, never by ordinal alone.
