# M2-R0 Architecture — Codex proposal v2

Design status: proposed; production source remains M1. Source basis: CodeWeave `6c3d1b8cf9c2ff3257c92840dd8531dcc1cceed7` (schema 3, fact protocol 2). No M2 capability below is implemented by this document.

## 1. Existing implementation and constraints

The actual path is `cli.main → build_index → _load_compilation_database/_safe_arguments → Bubblewrap → LibTooling Action/Visitor/Emitter → _collect → SQLite transaction → query → CLI/HTTP → React`. Source references below are relative to CodeWeave at that commit.

| Evidence | Architectural consequence |
|---|---|
| `analyzer/main.cpp:90–104,116–145` uses external USR and physical file/TU suffix for internal linkage; stores ODRHash | A temporary-copy path must not become cross-version identity. ODRHash is a conflict hint, not a collision-free semantic digest. |
| `main.cpp:148–182,200–234` emits evaluated calls, including spelling/expansion, lambda context and unknown dispatch | Preserve per-call evidence and honest static semantics; no runtime/dynamic-dispatch promises. |
| `main.cpp:258–268` emits SourceManager buffers, including macro-only headers | Current `unit_files` is a useful positive read-set, not a complete include-resolution dependency model. |
| `index.py:179–205,311–330` saves raw ccdb hash and sanitized command hashes; uses live read-only mounts | Read-only is not an immutable snapshot: a host writer can change the mounted file. A new capture boundary is required. |
| `index.py:224–290` merges cross-TU facts, validates anchors and rejects inconsistent buffer identities | Reuse must occur before aggregation; old aggregate rows cannot be naively split into TU facts. |
| `index.py:282–285` hashes target, dispatch and complete anchors into instance_id | File hash or line movement changes IDs; cross-version relation comparison cannot use ID set subtraction. |
| `index.py:339–372` commits all facts or rolls back; initial DB publishes through no-overwrite hard link | Preserve atomic successful publication. Failed attempts need separate metadata, not partial published graphs. |
| `index.py:93–112,463–588`; `app.py:16–113` share read-only, schema-checked queries | Preserve a shared bounded query kernel and strict index identity. Mutation orchestration is separate from query reads. |
| `frontend/src/App.tsx:26–59,81–103`, `graph.ts`, `sourceLocation.ts` | Keep historical selection, abort/epoch isolation, graph budgets and UTF-8-to-UTF-16 conversion; two-side Diff must apply the same rules. |

No full dependency scanner, filesystem snapshot service, Git index writer, incremental layer, workspace mutation HTTP endpoint, or semantic Diff exists today. Existing `units_complete` means all selected commands succeeded, not that every file in a repository was analyzed.

## 2. Chosen scope and alternatives

**M2-A:** explicit Refresh Workspace; capture saved bytes to a private immutable view; full reanalysis; append a complete immutable index; compare two explicit indexes. **M2-B:** reuse validated per-TU fact bundles, then materialize the same complete index format. No delta graph database, content-object deduplication service, watcher daemon, project build runner or editor-buffer integration in this phase.

| Option | Decision |
|---|---|
| filesystem events | Optional future dirty hints; overflow, coalescing and unobserved roots prevent correctness use. No daemon in M2-A. |
| Git status only | UI provenance and candidate enumeration aid; misses ignored generated headers, external inputs and compile configuration semantics. Never the cache key. |
| mtime/size only | Fast hint only; equal-size edits, timestamp restoration and path replacement defeat it. |
| explicit refresh + complete manifest hashes | Selected; costs capture IO but gives inspectable input identity. |
| live-source analysis plus before/after stat | Rejected as the consistency foundation; checks do not freeze content and can miss ABA changes. |
| delta SQL facts/shared blob store now | Rejected; retain full snapshots, simpler publication and deletion semantics. |

## 3. Identity and capture

### 3.1 Four distinct IDs

1. `repository_id`: local configured repository identity, independent of current branch. No remote upload required; origin URL is descriptive, not an identity proof.
2. `base_git_head`: validated object ID plus object-format/tree ID observed from Git; nullable for non-Git workspace. It is provenance, never a claim that disk equals HEAD. Separately `represented_git_commit` is set only for raw Git-tree capture or exact verified tree equality of the project file vector (paths/types/modes/bytes); it is null for dirty disk captures. Staged/unstaged/untracked and ignored analysis-input changes are recorded separately. A clean Git status alone cannot set represented_git_commit.
3. `snapshot_id`: SHA-256 over versioned canonical manifest, sorted `(root_role, relative_path bytes, kind, effective mode, content_sha256 or link metadata)` plus capture policy, compiler-observable preserved input attributes (including mtime when relevant), and raw ccdb bytes hash. Refers to the saved, sealed file vector. Does not include random cache-directory paths. All paths in the manifest use a lossless encoding; invalid UTF-8 names are explicitly rejected in M2-A, not silently replaced. No unsaved editor buffers.
4. `index_id`: unique successful publication ID referring to snapshot_id + build_profile_id + analyzer/protocol/semantic-policy identity + observed input manifest. Reanalysis may yield another index_id for the same snapshot. One index_id never mutates its facts or bytes.

`build_profile_id` hashes canonical sanitized argv for every selected TU in sorted order, logical cwd/root mapping, selected TU set, explicit dependency/toolchain roots, resource content identity, Clang/analyzer binary identities, fact/query semantic policy versions and relevant environment policy. Save raw ccdb hash separately. A harmless ccdb reordering changes raw provenance, but not normalized profile. Identical commands deduplicate; incompatible commands for one TU reject `multiple_configurations` until an explicit profile is selected. Separate profiles never merge facts silently.

### 3.2 Capture protocol

- Workspace roots, dependency roots, ccdb, analyzer and toolchain are trusted startup/CLI configuration; HTTP never accepts arbitrary host paths. A capture enumerates **all regular files in declared analysis roots**, including ignored/generated files that are not explicitly excluded, before parsing. Exclude `.git`, CodeWeave's own database/cache and declared unrelated artifact roots. Exclusions are stored policy; an include needing an excluded file fails, never falls back to the host. A large root hits a documented file/byte quota and fails clearly; do not silently truncate.
- Store private captures outside imported source, default owner-only directories. Copy bytes via pinned directory descriptors, reject devices/FIFOs/sockets and unsafe link traversal. Root symlink authorization resolves to a physical directory. First M2-A rejects project/dependency symlinks in captured namespaces with `unsupported_snapshot_link`; it does not follow them outside authorization. An unrelated excluded directory may contain links. Trusted standard-toolchain bundles may preserve aliases only after validating every link chain against the sealed authorized namespace: record link spelling and target, reject dangling/cyclic/escaping links, and never preserve a pointer to live host content. This exception is required for ordinary installed standard headers and is tested independently. General project alias support is deferred until alias/physical identity tests pass; hardlinks are read as ordinary bytes, not retained as writable sharing.
- Capture namespace inventory and per-file bytes/type/mode before/after copying, using open-descriptor identity checks and hashes; compare ccdb and HEAD/status observation before/after too. On detected change discard/retry once, then `workspace_changed_during_capture`. No stat-only acceptance. Seal copies and verify them before analysis. A private generation has one coordinator and is never reused while incomplete. Root mappings must be disjoint (identical roots deduplicated); otherwise reject overlapping_snapshot_roots before capture. Check trusted output/cache paths cannot be beneath an analyzed input root or shadow a declared input.
- A normal filesystem cannot prove a simultaneous multi-file instant against arbitrary noncooperating writers. The supported identity is the **explicit sealed vector of copied bytes**. Repeated inventory/hash scans detect common races but are not an atomic filesystem transaction. Never label it an exact wall-clock disk instant. If the source changes after sealing, analysis remains on the sealed vector and returns `workspace_changed_since_capture=true`; the next refresh observes new bytes. Two TUs cannot read different versions of the same sealed header.
- Mount the sealed project copy at its original authorized absolute path inside a fresh Bubblewrap namespace; hide the host live tree. Likewise sealed dependencies/configuration, and no fallback path to originals. Analysis uses these stable virtual paths, not the private cache path. Maintain an exact `(root_role, relative_path) ↔ sandbox physical path` mapping in provenance; anchors must refer to registered sealed bytes.
- System/toolchain **input** trees (the concrete Clang resource and standard/header search roots, not the entire host /usr) must be an immutable captured toolchain generation or an explicitly administrator-provided immutable image, keyed by complete manifest. Cache that generation outside the source with a lease; when preparing a new generation capture/hash/verify it just like dependencies. Do not equate a read-only bind of live `/usr` with immutable compiler inputs. Map only the trusted analyzer executable and its verified runtime ELF dependency files as execution inputs, not live /usr or broad /lib trees. Freeze and manifest those mapped file bytes too. Add the frozen header roots as separate directory binds; reject root/file mapping collisions. There is no general host filesystem fallback. Runtime binary files remain registered non-source execution inputs even if an absolute include attempts to read one; source API never serves them. Record actual trusted default include discovery/order and any explicit driver adjustment in build_profile_id, rather than silently changing compiler search semantics. Prove search-root confinement and ordinary C/C++ standard-header compatibility in M2-A. Retain M0's warning that this is not a portable/reproducible OS image. An environment unable to provide this boundary gets a clear capture/authorization error rather than weaker successful guarantees.
- Preserve and record input mtimes if required for compiler observations; volatile builtins (`__DATE__`, `__TIME__`, `__TIMESTAMP__`) mark TU `cache_eligible=false`, with actual analysis epoch/context recorded. Do not promise deterministic outputs for time-dependent preprocessing. M2-B must full-analyze such TUs.
- The capture manifest lists all inputs and relevant attributes/analysis entropy context; source API only serves registered project buffers, not dependency/system/private configuration bodies. Toolchain hashes and diagnostics are bounded provenance. No private inputs enter Git/workflow logs or third-party review.

### 3.3 HEAD view and new/deleted files

Use raw `git ls-tree -rz` + `git cat-file --batch` objects, not checkout/worktree, filters, hooks or build commands. Set `GIT_OPTIONAL_LOCKS=0`, disable fsmonitor and external/textconv helpers; sanitize inherited Git environment. Validate `.git`/alternates authorization. Submodules and LFS pointers are explicit unsupported/incomplete inputs unless separately authorized/materialized; do not fetch. Mode/type/path validation applies equally to tree entries.

HEAD snapshot contains that tree's bytes. Its ccdb must either come from that tree or be an explicitly supplied, labeled baseline profile. Do not copy Workspace generated headers or macros into HEAD under a HEAD label. External generated inputs may only be shared as explicitly identified common inputs, with this provenance visible. Missing historical generated files or unusable command paths block the HEAD side, not Workspace analysis; do not run CMake to recreate them. This limitation is a visible acceptance case, not a silent HEAD↔Workspace comparison.

Workspace capture uses disk bytes whether staged or unstaged; the saved Git index supplies provenance only. Added TU needs a valid selected command; a new unlisted `.cpp` appears as `uncovered_file` and prevents `repository_complete`, but not honest selected-units publication. Deleting a TU without updating ccdb fails as `stale_compilation_database`; dropping its command deliberately changes selected scope and must not imply symbol deletion without the Diff scope rules. Rename is path removal/addition; Git rename detection is a UI hint, never identity authority.

## 4. Refresh state machine and publication

`queued → capturing → sealed → analyzing → validating → publishing → published` or terminal `failed/cancelled/superseded`. Attempt has stable request_id; successful publication has index_id. Single writer/refresh lease per configured workspace; concurrent refresh returns `refresh_busy` with active request ID. Queries continue using their pinned successful index. Crashed nonterminal attempts become `interrupted` on service recovery; no automatic execution on restart.

Host edits during analysis cannot affect sealed inputs. Before commit verify sealed hashes, all selected-TU outcomes, input-to-anchor hashes, config/toolchain IDs and facts schema. Reaggregate all complete TU facts and validate constraints, then insert **all** index rows and atomically update the workspace's current_successful_index in one short SQLite transaction. No file-by-file publication or per-TU success masquerading as a complete new graph. Warning is allowed and counted; driver/frontend errors, missing headers, invalid protocol and one failed TU fail the attempt. Save per-TU failures separately, with no new published index; old snapshots/source/queries remain intact.

Refresh requests have generation/base_index_id (compare-and-set). Even with one writer, a stale requester cannot overwrite a newer publication; `workspace_generation_conflict` returns the successful index to reload. Aborting an HTTP request does not invent job cancellation; explicit job cancel stops only the owned worker and fails publication. Cleanup never deletes the latest successful or pinned/leased source generation.

M2-A may synchronously execute from CLI while exposing the same job lifecycle. HTTP creation returns 202 promptly; worker is a local bounded subprocess started by explicit trusted refresh, no durable distributed queue. Browser closing is not publication authorization revocation. Server startup never begins a build or runs imported repository commands.

## 5. SQLite schema 4 and lifecycle

Keep complete index-local `files/units/unit_files/symbols/symbol_units/calls/call_units`. Add:

| Table/field | Purpose and constraints |
|---|---|
| `snapshots(id, manifest_version, capture_policy, base_git_head, represented_git_commit/tree, raw_ccdb_hash, manifest_json, sealed_at)` | Immutable capture identity and explicit Git provenance; large manifest not returned by default. |
| `indexes.snapshot_id, build_profile_id, semantic_policy, source_kind` | Non-null for M2; nullable only for imported legacy records labeled `legacy_observed_inputs`. No invented old workspace identity. |
| `workspaces(id, configured_roots_identity, generation, latest_successful_index)` | Trusted local configuration references; atomic CAS publication; FK latest points to published index. |
| `refresh_attempts(id, workspace_id, base_generation, state, candidate_snapshot_id, result_index_id, timestamps, error_code)` | Failed attempts remain traceable without publishing facts; checked terminal-state transitions and FK constraints. |
| `attempt_units(attempt_id, tu_key, state, diagnostics, command_id)` | Bounded queryable warning/error/scope provenance, complete failing TU enumeration. |
| `symbols` evidence fields / `calls` syntax evidence | Definition byte ranges/hashes, semantic USR, linkage owner, namespace mapping, and cross-version call correspondence evidence (protocol 3 below). |
| `tu_artifacts` (M2-B only) | Complete versioned per-TU raw facts + input/config digest, artifact checksum and origin index. File cache entries are private, validated, leased; no delta facts layer. |

Use composite FKs matching existing index-local identities, explicit checks on scope/state and nonnegative extents, unique workspace generation, indexed attempt state and comparison/sort keys. Target symbol is nullable/external as today; do not add an FK that rejects honest external calls. All query paths open `mode=ro`, validate an explicit known schema and never run migration. Write connection enables FK and short transaction/busy timeout; database_busy is retryable JSON. Start with existing rollback journal, not network SQLite/WAL architecture. Measure read blocking; WAL is an explicit later choice, not a guarantee from this design.

**Migration:** explicit offline `migrate --from old --to new` to a new path. Open schema3 read-only in a SQLite read transaction/backup-consistent view; validate version and relational integrity; copy original facts/IDs/bytes into schema4 with legacy provenance. Validate row counts, per-index content and FK/integrity, then close/fsync the completed destination, atomically link it without replacing any existing path, and fsync the parent directory. An orphan completed temporary file is not a published index and can be reclaimed by owned migration metadata. Source and old readers remain unchanged. M2 readers support exact schema3 read-only for legacy facts plus schema4; legacy indexes lack trustworthy workspace snapshots/definition ranges and Diff returns `not_comparable_legacy_index`, not fabricated equivalence. Rebuild both sides for M2 comparisons. Migration failure leaves source and default successful index untouched. No in-place auto-upgrade, no down-migration.

**Lifecycle:** complete snapshots intentionally duplicate facts/bytes initially. Disk quota checks before analysis and commit; ENOSPC aborts without switching default. Manual bounded `indexes prune --dry-run`, then explicit administrative prune (future M2-B subtask); no automatic history deletion in M2-A. Never prune latest, pinned two-side comparisons, active job inputs or leased cache. Removing one index must not break any retained source. Abandoned private generations can be removed only by owned-attempt metadata and lease checks, never by broad glob/rm on imported roots. DB compaction is explicit offline maintenance, not query side effect. Record estimated/reclaimed bytes and quota errors; do not promise unbounded history or constant storage.

## 6. TU dependency and reuse rules

### 6.1 Actual information and missing information

Today `unit_files` supplies successful SourceManager reads per TU with content hashes, including headers that only define macros. It does not record all failed path probes, include search shadowing or negative `__has_include` dependencies. A new earlier-search-path `config.hpp` or previously absent optional header may change the AST while all old read files remain unchanged. External inline definitions can differ by configuration; no TU reuse solely from `.cpp` bytes.

In protocol3 use existing SourceManager buffers as truth and LLVM18 `DependencyCollector`/`PPCallbacks` for dependency diagnostics and completeness: include directive result, `FileSkipped`, macro expansion and `HasInclude`, system inputs included intentionally. **Callbacks alone are not a proof of every candidate path probe.** Keep a conservative namespace inventory rule even after adding them. Do not implement a homemade preprocessor or parse include strings with regex.

### 6.2 M2-B invalidation algorithm

For a newly sealed capture:

1. If analyzer/Clang/protocol/semantic policy, global root/search-policy mapping, toolchain generation or dependency-collection version changes: full rebuild. A profile-family/configuration-selection switch is a full rebuild; a command change within that supported family is handled per TU in step 2. The whole build_profile_id still changes, while unchanged TU context keys may be reusable; never use equality of the whole profile ID as the sole per-TU condition. Any unsupported/incomplete input observation or corrupt/missing artifact is a cache miss, never a successful empty TU.
2. Compare normalized commands/TU membership. A changed command invalidates its TU; added/removed commands trigger scope revalidation and full aggregation. If profiles are incompatible, report configuration divergence in Diff rather than blend facts.
3. Compare inventories of **all authorized include namespaces**, not only consumed files. Any path addition/removal/rename, directory/link/type/search-root change invalidates all TUs initially. This covers negative probes, new shadowing headers and newly present `__has_include`; optimize only after explicit dependency-resolution proof. An unchanged inventory + changed bytes invalidates every TU whose old read-set contains that physical/logical path. Changed TU source is itself a dependency. Header transitivity is already represented by the read-set.
4. Reuse only if previous successful TU artifact exists, all read input bytes/attributes and command context agree, namespaces unchanged, no volatile builtin, and checksum/protocol/coverage complete. Analyze all other TUs against the same sealed generation. External internal-linkage ownership remains scoped by logical TU. Reused fact anchors must still validate against that generation, with origin TU/config/index recorded.
5. Union complete fact bundles and run the same deterministic merge/ODR-conflict/anchor validator as full rebuild. Removed TU facts are absent; shared external entities survive observations from retained TUs; there is no append-only residual relation bug.
6. Initial M2-B is a **validation mode**: shadow full rebuild from the same sealed generation, compare canonical complete facts including provenance/anchors/diagnostics (excluding timestamps/request IDs and reuse annotations). On mismatch reject incremental candidate, log mismatch and publish only validated full result; corrupt full result fails normally. This is not an end-to-end speed claim, since shadow analysis costs time. Measure incremental-only work and total time separately. Disabling mandatory shadow validation for production speed needs a later evidence-based decision, not an implicit R0 promise.

Same shared header under distinct per-TU flags is legal; its content key is shared but TU context differs. Different configurations for the same TU remain explicitly rejected/selected into separate profiles. A macro-only config edit invalidates its consumers even without any entities in that file.

## 7. Diff definitions and confidence

Comparisons take two explicit published index IDs from the same configured repository and semantic policy. They never read current disk or infer missing facts from a failed attempt. Failed attempts are attached status evidence next to the last valid index, not an empty side. A comparison has `comparison_id=hash(left,right,policy)`; stable bounded pagination sorts by event kind and logical entity/site key, never timestamps. Same index pair/policy has the same results after restart.

### 7.1 Entity matching

Use external semantic USR + repository namespace; internal/local entities additionally own logical declaration path and logical TU. This requires protocol3 to preserve `semantic_usr`, linkage/owner and normalized logical paths instead of stripping ad hoc `@file/@tu` strings from arbitrary USRs. Compiler-generated lambda/local identities may change with edits; match only when stable declared owner and exact evidence are unambiguous; otherwise added/removed/ambiguous, never speculative merging by name.

Overloads and same-name statics remain distinct. Cross-root temporary paths cannot affect identity. Renaming a TU changes internal-linkage identity; classify conservative remove/add with a file-rename hint, no guarantee of semantic continuity. External entities keep USR when Clang does, so relocation is separate. Different Clang/policy, repository or unsupported profile mappings return `indexes_not_comparable` or an explicit configuration comparison, not silently merged graph deltas.

### 7.2 Definition changes

Protocol3 adds validated Clang definition source ranges `(path, begin_offset, end_offset_exclusive, buffer_hash)` and raw range SHA-256; ambiguous/multi-file macro-generated extents are marked `unavailable`, not synthesized from line text. Preserve ODRHash as a nonauthoritative hint only. Adding blank lines **outside** the range changes location but not definition bytes. A changed byte range is `definition_text_changed`; whitespace/comments within the range are text changes, not a claim of different runtime behavior. A changed macro/config/read-set with identical definition bytes is `definition_context_changed` (possible effective change, with exact changed inputs), not falsely unchanged. Literal changes must be detected even when call edges and USR stay identical. Unknown range means `definition_comparison_unavailable`; an ODR hash match cannot fill the gap.

`added/deleted` require matched analysis domain and complete relevant TU coverage. An entity is removed only if its complete logical identity is absent in the comparable new domain. A removed definition with a surviving declaration is definition_removed, not symbol_removed; the inverse is definition_added. A removed entity in a still-selected successfully parsed TU is a deletion. If an entire TU command is dropped, show `out_of_scope` unless an explicit scope reconciliation establishes deliberate source removal and complete new coverage. A genuinely deleted tracked file plus matching command removal is a confirmed file deletion; its exclusive internal entities can be deleted, while external symbols require checking all old observing TUs and complete retained/new relevant coverage. For missing result/failed TU, report unknown/failed, never deleted.

### 7.3 Relations versus call instances

Semantic static relation key is `(caller_entity_key, target_entity_key or unknown kind, dispatch)`; aggregate counts are counts of distinct syntax calls under existing TU deduplication, not runtime executions. Compare multisets of relation keys and counts independently of anchors. A position-only edit yields unchanged relations/counts plus moved evidence; a second call adds one instance count even if the aggregate relation already existed. Shared external inline observations deduplicate; header-internal calls per TU remain distinct entities.

Stored instance_id remains index-local. A location/site view pairs call instances only by a verified correspondence: same matched caller, same structural call context and unique surrounding token context with normalized callee leaf excluded; require one-to-one matching and consistent macro spelling/expansion path. Repeated indistinguishable calls remain `ambiguous_correspondence` and are presented as old/new site evidence; do not invent a target-change pairing from line proximity or list ordinal alone. Simple unique `return old_target(); → return new_target();` must yield confirmed `target_changed`, backed by both endpoints/anchors and unchanged unique surrounding context. This correspondence algorithm and protocol3 evidence extraction is an explicit M2-A task, with adversarial duplicates mandatory. If it cannot meet these tests, M2-A is not accepted merely because relation add/remove works.

Unknown function pointer/dependent targets stay unresolved; changing unknown to known is `resolution_changed`, not proof of runtime target change. Ordinary virtual dispatch compares static declaration target/dispatch kind; explicit qualified base call is direct. A changed analysis profile is reported at comparison scope; changes cannot be attributed solely to saved source. Evidence on every event includes both index IDs, source snapshots/hashes, entity/site identities, config/TU provenance, confidence/reason and bounded links to before/after source. Never include full arbitrary source/commands by default.

## 8. Shared query and minimal interfaces

Existing queries and source budgets remain. Mutation orchestration calls the same capture/analyze/publish service from CLI and HTTP; query core is read-only. Interface sketches are a contract proposal, not current CLI commands.

| CLI | HTTP | Contract |
|---|---|---|
| `workspace status` | `GET /api/workspace` | Configured workspace ID, HEAD provenance, latest success, last attempt, dirty hint and known coverage. No automatic full hash scan or refresh. |
| `workspace refresh --expected-generation N` | `POST /api/workspace/refresh` | No client path/command fields; request has generation and idempotency token. 202 `{request_id,state}`; repeated same token+payload yields same job; conflicting payload 409. |
| `workspace attempt ID` | `GET /api/workspace/attempts/{id}` | Bounded state, counters, published index or error; per-TU diagnostics separately paged/chunked. |
| `query indexes` | existing `/api/indexes` | Explicit snapshot/source-kind/config summary; stable index IDs. |
| `query diff --left ID --right ID` | `GET /api/diff` | Summary/coverage/config comparability + comparison_id; no unbounded event list. |
| `query diff-symbols/calls --left ID --right ID ...` | `GET /api/diff/symbols`, `/calls` | Limit 1..200; immutable pair/policy-bound cursor; stable sort; total/returned/has_more; unknown/ambiguous flags. |
| `query source --index-id ID ...` | existing `/api/source` | Index-qualified saved buffer only; keep 200 lines/32768 raw bytes, query JSON ≤262144, status ≤32768. |

All new summary responses ≤32768 serialized UTF-8 JSON bytes; event pages ≤262144; fields ≤2048-byte previews with hash and bounded 4096-byte base64 provenance chunks as existing status. Budgets include metadata and next cursor; no complete manifest/argv in default response. Requests constrain all IDs/limits/offsets/ranges. Errors retain `{error:{code,message}}`; CLI failures exit2/stderr one object, no traceback/stdout mix; HTTP 404 unknown ID, 409 stale/busy, 413 budget, 422 malformed, 503 unavailable/schema. New error codes include capture quota/link/inconsistency, attempt incomplete, profile divergence and legacy incomparability. Query semantics/JSON facts match CLI and HTTP; transport envelope/status is documented.

**Mutation security:** remain loopback with Host/same-origin checks, but existing GET-oriented defenses are insufficient for POST. HTTP refresh is disabled under the existing read-only serve invocation and requires an explicit trusted allow-workspace-refresh startup policy. Once enabled, refresh requires JSON Content-Type plus an unguessable startup session token in a custom header, exact Origin when browser-supplied and no permissive CORS; reject simple cross-origin form POST and DNS rebinding. CLI has trusted local configuration, not browser token. The token is delivered by a same-origin no-store bootstrap response subject to Host/Origin/CORS restrictions, never by a cross-origin readable resource. It never appears in URL/logs/Git. This defends browser-origin attacks, not a malicious process with the same OS-user permissions as the configured CLI. No shell, project hooks, build scripts, plugins, response files, forwarded unsafe compiler flags or arbitrary repo scripts. All original whitelist/raw-argv checks still precede LLVM. Worker enforces CPU/time/disk/concurrency limits and owns only its output paths.

Frontend: explicitly select left/right indices; show scope/config/failed-attempt banner before deltas; fetch bounded changed-symbol/call pages, expand a local graph only within current budgets; separate selected-pair request epoch/controllers and per-side source. Never mix endpoints from different index pairs or refresh to latest over manual selection. A newly published workspace index is offered as a choice; historical selection remains. Both panes readonly saved snapshots, raw physical byte positions and correct Monaco UTF-16 navigation. No M2 UI is built in R0.

## 9. Implementation contracts, stops and rollback

M2-A deliverables: capture/pinning/root policy; Git HEAD raw view; schema4 explicit migration/legacy read; refresh state machine/atomic publication; protocol3 identity/ranges/site evidence; conservative Diff with unknown/ambiguity; shared bounded CLI/HTTP; two-version local UI. All full analyses; dependency metadata kept for explanation. Stop if any safety/consistent-bytes/identity/deletion/CLI budget contract fails. Revert new deployment to M1 using unchanged schema3 input DB; new schema4/output cache is separate, never rolled back into schema3. No automatic main merge is required for development: branch from verified M1 if PRs remain pending.

M2-B begins only after A independent acceptance: raw per-TU artifact cache, conservative invalidation, reuse/full shadow oracle, metrics and fallback. Acceptance requires zero canonical semantic/provenance differences across the defined edit matrix, demonstrated cache misses for negative includes/config/toolchain changes, corrupt cache safe fallback, old index survival, and measured compile/capture/merge/shadow costs. No fixed speedup percentage without measurements; report cases with no savings. Disable incremental reuse and run A on any unsupported cache situation.

Excluded: autosave/editor buffers, watcher daemon, executing imported builds, whole-program runtime/virtual resolution, complex PCH/modules, distributed storage, arbitrary historical build reproduction, large RMC performance, rename/lambda heuristic continuity, M2 production implementation during R0. M2-A user-visible header/ordinary-method/identity/snapshot/safety contracts are mandatory, not optional limitations.

## 11. Implementation details fixed before the design gate (v2)

### 11.1 Call correspondence is deliberately restrictive

Protocol3 records an AST-derived call syntax path within its enclosing definition and byte/token extents for the callee and enclosing expression where unambiguous. Use Clang Lexer/token ranges, not regex re-parsing. Definition-local tokens retain literal/argument/operator/member qualification spellings; skip comments/whitespace only for correspondence, retaining exact source bytes separately. Each verified direct callee leaf interval may be replaced by a placeholder. Build a correspondence candidate graph within one matched caller only when both definition token sequences (with those placeholders) are exactly equal, call form/argument tokens and macro spelling/expansion structure agree, and the non-position call-context fingerprint is unique on both sides. Require a one-to-one candidate. AST ordinal alone is never sufficient.

For a unique `return alpha();` to `return beta();`, this yields a target change from real Clang targets; identical normalized tokens with unchanged targets yields moved/unchanged evidence as appropriate. For two identical `alpha(); alpha();`, unique context fails: expose ambiguous site correspondence even though relation count differences remain exact. Insertion/deletion, overload-context changes, macro-generated non-contiguous ranges, reordered calls or unsupported token evidence may deliberately yield unmatched/ambiguous sites rather than a speculative pairing. Relation multisets are computed independently and remain authoritative within coverage. Protocol3 completeness validation distinguishes range unavailable from a missing fact. A claimed match includes both evidence hashes and method version, not a numerical confidence score with no empirical calibration.

### 11.2 Capture feasibility evidence and remaining engineering work

Owned Bubblewrap experiments against the actual M1 analyzer showed: (a) mounting sealed copy at the original virtual project path keeps internal identities on that path while a later host macro edit is invisible to analysis; (b) `<vector>` and `<cstddef>` parse with only individual runtime ELF files plus copied `/usr/include`/Clang resource input trees, without a broad live `/usr` bind; an owned absolute sentinel outside that view returns file-not-found and its marker is not read. The header-copy time on this machine was about 0.46s, not a portable performance claim. Those experiments are local feasibility evidence only: they did not implement descriptor-safe capture, race detection, complete alias validation, immutable runtime-file copying or the M2 production sandbox. Those are mandatory A tasks/negative tests, not already-passed guarantees.

### 11.3 Publication durability and configuration ownership

A schema4 writer uses synchronous=FULL on a supported local filesystem, one owned refresh lease and a short final transaction containing the complete new index plus CAS default update. After successful new-database creation, close/fsync file and fsync its directory following no-overwrite publication. Already-existing DB durability relies on SQLite journal/commit protocol, not renaming an open database. Failed attempts are committed separately from successful facts/default updates. Startup may mark owned nonterminal attempts interrupted but never replay imported commands. A forced OS/power failure is tested only to the guarantees of SQLite/filesystem; storage that violates flush contracts is outside the local product guarantee.

Before the worker starts, trusted configuration chooses the authorized project/dependency/header/runtime roots and selected compilation profile; clients choose only configured workspace/profile IDs, not host paths. If the current supported header configuration cannot be captured or has unsupported links, return an explicit unsupported/capture error; the normal system-header fixture must pass, so blanket rejection of installed toolchains cannot pass A acceptance.
